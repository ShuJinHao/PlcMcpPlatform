# 第一步计划：建立可持续开发的项目基线

版本：0.1；制定日期：2026-11-06；阶段：P0。

## 目标与范围

建立公有项目仓库、需求与架构基线、可构建的核心工程。全部设计服务于同一个闭环：工程师在 OpenCode 提出编程需求，OpenCode 读取工程上下文，调用 MCP 修改真实工程，读取编译诊断并迭代修正，最终保存可在 InoProShop 中打开的工程。

P0 提供结构和验证起点，不将目录、接口和模拟结果计为真实汇川功能。

## 本步工作包

| 编号 | 工作 | 交付与完成条件 |
|---|---|---|
| P0-01 | 创建 `PlcMcpPlatform` 公有 GitHub 仓库 | 仓库可访问且显示 Public，首次提交包含本基线 |
| P0-02 | 固定需求和能力范围 | 需求编号、完整能力矩阵、明确非目标和验收场景 |
| P0-03 | 确定架构与选型 | 领域边界、依赖图、数据归属、Worker 边界、版本化规则 |
| P0-04 | 建立核心工程 | .NET 8 解决方案、领域行为、端口、能力登记、EF 映射、MCP Host |
| P0-05 | 建立验证入口 | 构建、领域/并发/能力/架构测试、HTTP MCP 冒烟测试、CI 配置 |
| P0-06 | 完成交接 | README 可导航，OpenCode 示例可理解，已实现/未实现状态可核对 |

## 后续实施顺序

| 阶段 | 依赖 | 交付 | 退出条件 |
|---|---|---|---|
| P1：IDE 能力普查 | P0 | Windows 执行器探针、版本和能力证据、工程读取、编译诊断试验 | 记录真实 IDE/Profile/脚本引擎/模板版本；目标工程读取和编译证据可复现 |
| P2：可靠执行 | P1 | Worker IPC、数据库迁移、任务持久化、Channel 调度、互斥与恢复 | 排队恢复、重复请求、进程崩溃、取消与结果未知行为通过故障测试 |
| P3：工程编程闭环 | P1、P2 | 工作区、工程、POU、GVL、DUT、读回、保存、编译及诊断反馈 | OpenCode 完成一个真实模板工程的修改与错误修复，重开工程验证 |
| P4：工程组态与语言覆盖 | P1；写操作依赖 P2 | 设备、任务、库、图形语言、XML 交换 | 每项能力以真实版本和样例验收，不能实现的记录范围和原因 |
| P5：发布验收 | P3、P4 | 离线交付、运行账户、部署方式、兼容矩阵、完整验收 | 用户环境完成 OpenCode + InoProShop 联调并留存脱敏证据 |

P1 同时调查 ST、LD、FBD、SFC、CFC；先后实现顺序根据真实 API 与业务依赖调整，不能将 P3 的最小闭环解释成产品只支持 ST。

## P1 必需现场信息

- InoProShop 完整版本、Profile、安装路径、脚本入口和位数。
- 一个可以公开或内部使用的脱敏工程副本，控制器型号及设备描述/库依赖清单。
- 工程师登录会话中的执行结果；如需无人值守，再验证无 UI 和服务账户环境。
- OpenCode 实际版本与 MCP 连接结果。公开仓库不保存生产工程、商业库、厂商安装包或公司内部配置。
