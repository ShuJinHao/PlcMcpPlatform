# 需求文档

## 产品目标

面向使用 OpenCode 的 PLC 工程师，将自然语言需求转为真实 InoProShop 工程变更。模型生成程序，MCP 提供可发现、可验证、有约束的工程能力；业务正确性仍需要工程师结合设备规格、仿真和现场要求验收。

示例需求：“在指定模板工程中增加一个具备启停、自保持和报警复位的控制模块，并编译检查。”系统应读取现有对象与变量，创建或修改必要对象，明确任务调用是否已绑定，编译后给出真实诊断及保存结果。无法完成任务绑定时，不能声称该程序已进入运行任务。

## 功能需求

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-001 | OpenCode 通过 Streamable HTTP 调用 MCP | 完成初始化、工具发现和真实调用；业务层不依赖 OpenCode |
| FR-002 | 发现厂商、IDE 版本及能力 | 区分未验证、支持、不支持、暂不可用；附限制和证据 |
| FR-003 | 工作区和工程生命周期 | 创建/打开/关闭/保存/另存/备份；限定工作区，模板匹配控制器 |
| FR-004 | 读取工程结构与程序 | 稳定对象标识、父子关系、声明/实现、修订、输出截断标记 |
| FR-005 | 程序与数据对象编辑 | Program/FB/Function/Method/Property/Action、GVL、DUT、变量及组织对象 |
| FR-006 | 全语言能力覆盖 | ST/LD/FBD/SFC/CFC 分别验证读取、创建、修改和交换，不用语言枚举代替支持证明 |
| FR-007 | 工程组态 | 设备树、参数、任务、调用绑定、库、IO/EtherCAT 映射分项验证 |
| FR-008 | 编译与修复闭环 | 返回错误/警告/对象/位置和工程修订；模型修复后重新编译 |
| FR-009 | 工程导入导出 | CODESYS XML、PLCopen XML 按对象类型往返验证，记录丢失项 |
| FR-010 | 持久化执行任务 | 查询、取消、超时、幂等、互斥、重启后对账，不自动重放未知写操作 |
| FR-011 | 可审计工程修改 | 关联调用、任务、工作区、前后修订、备份、结果与编译报告 |
| FR-012 | 多厂商与版本扩展 | 能力端口 + ACL + 版本执行器，未来增加厂商不复制 MCP 协议层 |
| FR-013 | 在线能力登记 | 连接、监视、下载、启停独立能力和授权；当前阶段不暴露在线工具 |

## 非功能要求

| 编号 | 要求 | 验证方式 |
|---|---|---|
| NFR-001 | 当前 C# 工程使用 .NET 8 / C# 12 | 固定 SDK major，Release 构建 |
| NFR-002 | 内层独立于 MCP、EF 和厂商实现 | 程序集依赖检查 |
| NFR-003 | 同工程单写、同 IDE 的限制由适配器声明 | 并发提交、人工占用、跨进程锁测试 |
| NFR-004 | 已入队任务在重启后可识别 | SQLite 持久化与恢复测试；Channel 不作为事实来源 |
| NFR-005 | 错误可供模型采取下一步 | 稳定错误码、可重试标记和实际诊断；禁止吞错返回成功 |
| NFR-006 | 支持内网运行 | 后续离线包包含已许可依赖和锁文件；运行不自动访问公网 |
| NFR-007 | 默认仅本机访问 | 回环地址、鉴权、路径限制；远程部署需独立设计 |
| NFR-008 | 大工程输出有界 | 树查询分页/深度/数量限制，超限明确标记 |

实际 IDE 性能基线后续实测冷启动、编译和内存占用。当前默认最多 256 个未完成任务、单槽执行、超时 1～600 秒，属于保守开发配置，不作为真实 IDE 性能承诺。

## 核心验收场景

1. 指定模板与工程副本，读取结构、目标控制器和依赖库。
2. OpenCode 根据需求创建/修改程序与变量，并按预期修订提交。
3. 实际写入、读回、保存；在能力支持时完成任务调用绑定。
4. 引入一个可控语法错误，编译返回真实对象和诊断；OpenCode 修正后再次编译。
5. 关闭并重新打开工程，验证程序与配置存在，产物修订与最终报告一致。
6. 遇到人工编辑、重复调用、IDE 崩溃时分别返回冲突、同任务结果或结果未知。

编译通过不代表机器运行逻辑、功能安全或真实 IO 已验收。结果报告必须分别描述编译、任务绑定、保存和运行测试状态。

## 本期范围

当前实际实现见 README 与 docs/13～19；以上需求是完整产品基线。模型服务、RAG、OBot、Web 聊天界面、厂商 IDE 安装程序及任意脚本执行工具均不属于本项目首期交付。

## P5 补充验收要求

- 多对象生成应形成可审阅计划，按依赖顺序在一个候选中执行；整批验证和编译通过后只发布一次。失败保留旧头，未知结果不可自动续跑。
- 通用 XML 支持有界分块上传、重启恢复与完整摘要检查；工程请求只引用制品，不能把大文件复制进任务数据库。
- 交付包绑定准确 m2 修订，包含工程清单、依赖引用、任务绑定和编译报告；在副本上编译，不污染已发布源版本。
- 代码回归、发布检查、OpenCode CLI 连接、模型生成、真实 IDE 和 PLC 运行分别报告。集中回归工具首个失败即停，不能把模拟成功写成厂商支持。

本批实现与范围见 [docs/16](16-engineering-delivery.md)。

## P6 补充验收要求

- 接入已保存工程及明确声明的伴随文件，源预览修订、复制前后文件校验、依赖检查与首次托管发布形成闭环，保留原工程。
- Application 上下文、GVL/DUT、源码窗口、任务/库引用均绑定修订并明确分页或截断；不伪造完整调用图。
- 精确补丁要求完整源码摘要与唯一旧文本一致；通过既有批量保存重开、任务核对和编译后发布。
- 历史差异区分文件字节、源码文本和 graph-v1；恢复创建新版本，保留历史并验证全部 Application。

具体工具、限制和回归见 [docs/17](17-incremental-engineering.md)。

## P8 补充验收要求

- graph-v1 保持兼容，graph-v2 新结构具有独立字段校验和完整 XML 往返检查。
- 标签连线参与循环/执行顺序检查；SFC 分支顺序、优先级和汇合关系不能在转换中丢失。
- 类型和返回值变化进入版本差异；混合 ST/LD/FBD/SFC 工程通过既有批量与交付链路回归。
- 图形子对象与未知数据保护继续生效，离线成功不代表目标 IDE 已支持。见 [P8](19-graph-v2-engineering.md)。
