# 架构决策记录

| ADR | 决策 | 原因 | 重新评估条件 |
|---|---|---|---|
| 001 | OpenCode 负责模型编程，MCP 负责工程自动化 | 主路径清晰，服务可供其他 Agent 使用 | 出现服务端自主工作流需求 |
| 002 | 模块化单体 + 进程隔离 Worker | 保持本机部署简单，隔离 IDE/运行时/崩溃 | 多机执行或大量用户共享资源 |
| 003 | DDD 聚焦工作区和任务规则 | 工程快照不是数据库聚合，避免镜像厂商对象模型 | 出现独立业务不变量与生命周期 |
| 004 | 能力接口而非巨大厂商接口 | 各厂商/版本不必实现相同能力 | 公共语义无法表达新能力时版本化扩展 |
| 005 | .NET 8 / C# 12 | 符合现有开发环境 | 正式部署前升级受支持 LTS |
| 006 | SQLite 是任务事实来源，Channel 只唤醒 | 服务重启不能丢失已接受任务 | 多节点调度/高并发元数据写入 |
| 007 | 生产模式未验证能力不开放为工程工具 | 防止模型把接口存在当作可执行能力；独立测试宿主可用显式测试来源验证同契约工具 | 补足实际版本与样例证据后开放生产能力 |
| 008 | 结果未知不自动重放 | IDE/工程文件修改与数据库不能原子提交 | 有可验证幂等与恢复协议的特定操作 |
| 009 | 先验证用户会话，再决定服务化 | IDE 无 UI 不等于 Windows 服务可用 | 目标服务账户及依赖完整验证 |
| 010 | 图形语言全面调查、分项验证 | 不限制为 ST，也不承诺通用 XML 无损 | 新版脚本 API 或验证路径变化 |
| 011 | 公有仓库重新编写实现 | 参考架构习惯，不搬运既有私有业务代码 | 所有者明确授权复用具体代码并核对许可 |
| 012 | P0 不强制 MediatR/FluentAssertions | 保留 Handler 风格，减少基础依赖 | 管道/团队标准确有需求并核对版本许可 |
| 013 | 依据供应商文档与官网自主实现 PLC MCP | 第三方 PLC MCP 的覆盖范围不能决定本平台边界 | 用户明确改变实现来源要求 |
| 014 | 文档版本、运行时接口可见性与操作验收分开 | 文档缺页不等于不支持，接口存在不等于操作成功 | 取得目标版本和对象的可复现执行证据 |
| 015 | 一个 PLC 领域 MCP Server，厂商模块使用内部端口和执行协议 | 避免把适配器误建成下游 MCP，避免复刻 Obot 类通用网关；保留 PLC 工程规则 | 厂商服务确有独立部署/对外消费需求时重新评估；通用治理优先采用现有产品 |
| 016 | 开发与厂商验收分开安排 | 当前无 Windows/IDE 环境仍能实现服务、执行器和官方调用脚本；替身仅用于自动测试，不进入默认生产依赖或支持声明 | 取得目标 IDE 后补齐真实验收，不将其作为继续编码的前置条件 |
| 017 | 第一批每个工程任务拥有独立打开/关闭会话 | 避免接管用户现有 GUI 工程；open 当前为校验任务，长期会话按实测再评估 | 实际冷启动成本、许可与会话行为验证后 |
| 018 | 主文件 SHA-256 仅作为读取版本标记 | 文件哈希不覆盖依赖与未保存 IDE 状态，不能直接用于工程写事务 | P2 已增加 m2 文件清单修订；全球依赖和 GUI 内存仍另行验证 |
| 019 | 写入采用新候选与唯一版本目录 | 不覆盖源工程或历史版本；发布仅更新当前头，文件与数据库失败边界明确 | 存储容量与真实 IDE 文件布局实测后优化 |
| 020 | 模板、工作区与主文件修订分开 | t2 覆盖模板描述及文件，m2 覆盖版本身份及文件清单，读取 SHA 只覆盖主文件 | 新依赖范围需要显式扩展修订协议 |
| 021 | 未知任务只依据持久化事实对账 | 发布证据与头在同一事务，迟到执行器失去发布权；无法证明停止则继续阻塞 | 新的厂商终止/恢复证明可验证时 |
| 022 | 工程引用匹配不等于依赖已安装 | 控制器与库引用检查不能证明本机设备/库解析成功 | 取得目标 IDE 依赖解析与编译验收证据 |


Host 中的 `McpHost` 是可执行项目命名；在 MCP 协议角色中，该程序是 MCP Server，OpenCode 是承载 MCP Client 的应用。名称不改变协议职责。
